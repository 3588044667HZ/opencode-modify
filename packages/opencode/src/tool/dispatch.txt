Launch a team of subagents in parallel and aggregate their results.

Use this when a task decomposes into independent workstreams that can run concurrently. Each member runs in its own session with its own model, permissions, and context. Prefer a team when members do not need to read each other's output while running; use the Task tool for a single subagent.

When NOT to use this tool:
- If you want to read a specific file path, use the Read or Glob tool instead of a team, to find the match more quickly
- If a single subagent suffices, use the Task tool
- If no available agent is a good fit for the task, use other tools directly

Usage notes:
1. Give every member a self-contained prompt. Members start with a fresh context and do not see this conversation.
2. Prefer named teams configured in `team` when the user maintains a roster; pass `tasks` to override or run an ad-hoc team.
3. `mode` defaults to `join`, which waits for every member and returns aggregated results including each member's `sessionID`. If a join dispatch is interrupted or aborted, waiting stops but the members keep running detached; their completions are still recorded in your inbox and injected as `<=2KB` `<team_update>` summaries.
4. `mode: "background"` returns immediately. When each member finishes (completed or error), a compact `<=2KB` `<team_update>` summary is recorded in your inbox and injected into this session; the full result stays in the member's session and can be read later via its `task_id`. Then work on non-overlapping tasks.
5. `concurrency` caps how many members run at once (default 4). Keep it conservative; members consume tokens concurrently.
6. To continue a member's session later, pass its `sessionID` as `task_id` to the Task tool, or pass `task_id` on a member here to resume that session. Resuming a member that is still running appends the next prompt after its current turn.
7. A member is a subagent and cannot itself dispatch unless explicitly permitted.
8. `budget_tokens` stops the team once combined member token usage exceeds the budget; the aggregate reports total usage.
9. `variant` sets a member's thinking intensity (e.g. low, medium, high, max). It must match one of the member's effective model variants; unknown values fail before any member starts. Omit it to inherit the lead's variant when the member uses the lead's model. Pass `"default"` to explicitly use the model's default intensity.
10. `autonomy` lists external directories (absolute paths) a member may access without prompting. High-risk paths (filesystem roots, home, secret stores) are rejected and require human approval, and a path that conflicts with a deny rule fails before any member starts.
11. Interrupting or aborting a dispatch does not stop its members; they keep running detached. Use the team tool (`op: "stop"`) to stop them explicitly, including when a member stalls or waits on a permission.
